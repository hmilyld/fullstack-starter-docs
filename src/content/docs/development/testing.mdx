脚手架本身没有自动化测试框架，验证采用手动流程。

<Steps>

1. 生成测试项目

   ```bash
   npm run dev
   ```

   选择一个前端 / 后端组合与项目名，生成到工作目录。

2. 验证前端

   ```bash
   cd <项目>/frontend
   npm install
   npm run build
   ```

   构建应无错误。开发态可 `npm run dev` 检查页面与接口联调。

3. 验证后端

   ```bash
   # Python
   cd <项目>/backend
   uv sync
   JWT_SECRET_KEY="$(openssl rand -base64 48)" uv run uvicorn app.main:app --reload --port 8088

   # Java
   cd <项目>/backend
   mvn spring-boot:run
   ```

   确认后端能启动、数据库初始化并写入种子数据，且能用 `admin / 123456` 登录。

4. 验证 Docker

   ```bash
   docker build -t test .
   docker run -p 5173:5173 -e JWT_SECRET_KEY="$(openssl rand -base64 48)" test
   ```

   访问 http://localhost:5173 确认前端可加载、登录可用。

</Steps>

## 菜单与数据管理专项验证

1. 用管理员登录，进入菜单管理，调整分组顺序和菜单跨组顺序，保存后刷新页面确认顺序保持。
2. 创建自定义菜单并给角色授权，确认动态侧边栏出现；删除菜单后确认权限和授权同步消失。
3. 导出完整数据，确认下载成功并显示一次性密码，关闭提示后密码不可再次查看。
4. 使用正确密码导入刚导出的文件，确认导入期间普通接口返回 `503`，任务最终为 `success`。
5. 导入成功后确认旧令牌返回 `401`，能够使用导入包中的管理员重新登录。
6. 使用错误密码、损坏包和不兼容版本分别导入，确认失败回滚且普通接口恢复可用。

## 建议覆盖的组合

至少验证你改动影响的组合。由于前后端自由搭配，改动前端模板时也应在 Python 与 Java 两种后端下各验证一次；改动后端模板同理。

## 快速验证清单

- [ ] `npm run build`（脚手架）通过
- [ ] 生成的项目前端构建通过
- [ ] 后端可启动并完成初始化
- [ ] `admin / 123456` 可登录
- [ ] 权限菜单按角色正确显示
- [ ] 菜单排序、跨组移动和自定义菜单权限正确
- [ ] 导出包可解密并包含完整表清单
- [ ] 导入成功后会冻结普通请求并使全部会话失效
- [ ] 导入失败后事务回滚且系统解除冻结
- [ ] Docker 镜像可构建并运行
